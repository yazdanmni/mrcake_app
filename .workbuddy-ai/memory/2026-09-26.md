## Fixed along the way

- ⚠️ **The gift-card dashed divider overflowed only on wide screens**
  (`DottedDivider`). It counted dashes from **raw** `constraints.maxWidth` and then
  painted each dash with `.w`. Those are different units here (`.w`/`.sp` track
  `scaleWidth`, > 1 on a wide screen), so the row overflowed by a margin that grew
  with width: **51px at 768, 132px at 844×390, 370px at 1024×768** — and at
  390×844 it was invisible. Fixed by deriving the count from the *scaled* dash
  width. **Rule: never mix a raw `constraints.maxWidth` with a `.w`-sized child
  in the same calculation.** Found only because the new screens were finally run
  at the four sizes the project already documents.
- ⚠️ **`'$label:'` is resolved into two text runs in RTL**, so a label containing
  a colon cannot be shrunk by `Flexible` and overflows a `Row`. The gift facts are
  now stacked (label above value), labels are plain strings, and values wrap.
- ⚠️ **`find.text` and a scrolling list:** «هدیه ها» is one `ListView`, so a row
  below the fold fails `findsOneWidget` for a layout-unrelated reason. Use
  `tester.scrollUntilVisible` rather than enlarging the test surface.

- ⚠️ **`test/house_features_test.dart` hung for 10 minutes on the first
  «اعتبار شما» case.** Root cause: `SharedPreferences` has no platform channel
  in a test process, so `SessionManager.save` → `_persist()` → `getInstance()`
  never completes and the `await` never returns. The failure reads as a bare
  `TimeoutException after 10 minutes` with no stack and looks exactly like an
  infinite animation — a wasted `pumpAndSettle` investigation. **Any test that
  signs a user in must call `SharedPreferences.setMockInitialValues({})` first**
  (see `cart_screen_test.dart`, `orders_screen_test.dart`). Also added a warm-up
  `pumpWidget` before `ScreenUtilInit`, because `SplashScreen.initState` arms a
  real `Timer.periodic(hours: 1)` that `pumpAndSettle` would wait on forever.
- ⚠️ **`find.text('دوره')` does not match a `'دوره:'` `Text` in RTL.** The label
  lays out as two text runs, so a one-run finder matches nothing even though the
  word is visibly on screen. Assert the colon form.
